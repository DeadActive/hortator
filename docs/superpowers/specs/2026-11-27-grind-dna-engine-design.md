# GRIND DNA ENGINE — Hybrid Design Specification

**Date:** 2026-11-27  
**Status:** Approved product direction; proposed technical contracts for implementation review.  
**Baseline:** [DaFum/grind-machine main 67be119](https://github.com/DaFum/grind-machine/tree/67be119a59b11d0ae154217d9248becefca59190).  
**Execution:** [Implementation plan](../plans/2026-11-27-grind-dna-engine-implementation.md).

## 1. Product goal and scope

One intelligent extreme-metal drummer: RIFF INTELLIGENCE converts MIDI phrases into rhythmic intent, GROOVE DNA learns compact rhythm statistics, GENETIC BREEDING combines the rule sets of two GRIND styles and optionally those statistics, and DRUMMER BRAIN turns the result into a playable or intentionally machine-like performance. The FM-1 plays the existing eight roles K/S/H/R/C/X/TH/TL through its native cue, timing, voice and effects engines. This is a deterministic rule-based instrument, not an LLM or an audio classifier.

The user approved the hybrid architecture: standalone capture, generation, selection and performance on the device, with the computer/editor doing long-file analysis, recipe management, visual editing and optional preview. No cloud, mandatory account, subscription or external AI service. After a recipe/profile is loaded, playback and generation work without the editor. User can return to normal GRIND immediately; DNA is opt-in.

This extends, not replaces, [original T01–T24 and community quality policy](../plans/2026-11-27-grind-machine-implementation.md) and [the selected CoralFlower/FRASIL extensions](../plans/2026-11-27-grind-community-feature-expansion.md) (PR #12). Hardware alpha stays first; DNA tasks are not new prerequisites for the existing alpha. Do not include unselected screen mirror, organism, project restore, performance recording, Song Architect, new audio engine, arbitrary long song recorder, guitar audio recognition, or new hardware/BLE target. A standard audio guitar needs an external MIDI converter or a future editor-side analysis project. MIDI note durations and attacks do not identify palm-muting or articulation with certainty.

Hardware status BLOCKED (not tested). Re-measure at each integration because the community extension also consumes memory. No added global threshold, headroom percentage, latency/soak target, arbitrary hardware certification or second CI release system.

Data flow:

    MIDI input -> selected-source capture -> immutable last complete riff
    Local song analysis -> GDN1 profile (statistics only)
    Parent A + Parent B + profile + riff + seed -> DNA rule resolver
      -> bounded candidate -> drummer coordination -> shared validation
      -> existing main-loop stage -> cue END / stopped atomic commit
      -> existing 8-track sequencer / P-LOCK / MOTION / LFO / FX / MIDI
    Native commit acknowledgement -> active recipe, preview, undo and editor

All generation, profile parsing, crossover, limb assignment and formatting are main-loop/host work. ISR only consumes existing MIDI ring, writes compact capture bins and publishes an already validated native stage at the existing boundary. Never generate or parse files in ISR, allocate on audio path, change HAL/loader, add a second scheduler or raise DRUM_MAXV to hide overload. Only one full candidate uses existing gmrt.out and base/stage union. Temporary rule masks and capture/profile storage have measured lifetimes, not speculative overlapping aliases. Reuse existing stack/work buffers after checking stack/map. No additional full pattern arrays in permanent RAM.

## 3. Common musical contracts (DNA-01)

Stable parent IDs are the existing 22 styles, not a new factory enum or a hidden style 23. Initial native DNA targets uniform STEP-source grids with all eight lengths equal, shared division and compatible swing; 4/4 first, then whole-quarter meters (3/4, 5/4, 6/8) when rules are representable; 7/4 only after EA1 implementation. Fractional-quarter meter per bar (7/8, 9/8) is unsupported in DNA v1, not removed from legacy GRIND. Explicitly refuse unsupported parent/grid combinations (including segmented/Polymetric length mismatches). Host may analyze other meters but must report normalization/unsupported inputs. No silent truncation beyond 64 steps, or change to device tempo, source, routing, kit or transport. Native bpm remains in supported descriptor range; portable gm_config continues its own 40..350 range. Use the existing native cue END, not an invented bar scheduler. No claim of 7/4 implementation from a plan alone.

Priority:
1. Original base context, transport and lock ownership: G-LOCK preserves whole ON/OFF cell, timing required to preserve it; P-LOCK and MOTION events stay at their exact stored locations and values. DNA treats P-LOCK/MOTION coordinates as temporary protected cells and keeps their track timing; does not promote them to persistent G-LOCKs. A protected out-of-length cell, incompatible timing or impossible request yields GM_LOCK_CONFLICT; never discard it.
2. In selected parent rule groups, preserve required anchors, required rests, paired hits, necessary ratchets and required accents; a G-LOCK override of a musical anchor/rest is permitted and reported, not erased. In the DNA-enhanced path, paired groups with one protected conflicting member refuse or honor the complete protected group with explicit override; no orphan pairing. The legacy-identity branch in section 5 retains existing protected-cell exceptions. Existing native portable ceiling and real target/audio checks always apply, even to MACHINE.
3. Riff and DNA bias optional opportunities only; mutation cannot remove hard anchors, create hits in required rests, or alter protected cells.
4. Human-profile coordination removes/de-ratchets optional strikes deterministically. If hard/protected events cannot be assigned, report conflict and keep current live pattern. MACHINE bypasses human heuristics only.
5. Shared structural and effective-rule validation plus native adapter validation; publish atomically only on accepted revision. No changes to live state, config, recipe, dirty, seed or undo on failure or no-change.

## 4. GROOVE DNA (DNA-02)

GDN1: exactly 88 canonical bytes; integers only on device. LE unsigned fields, signed micro bytes explicit two's complement. No struct dumps, names, file paths, raw notes or audio. FNV-1a-32 gm_hash over bytes 0..83, stored LE at 84..87, integrity diagnostic (not crypto/auth). Version 1 only; reserved bytes zero.

| Offset | Bytes | Meaning |
| --- | --- | --- |
| 0 | 4 | ASCII GDN1 |
| 4 | 1 | schema 1 |
| 5 | 1 | micro-known role mask |
| 6 | 1 | accent-known role mask |
| 7 | 1 | zero |
| 8 | 16 | eight u16 rate values Q8 occupied cells/quarter (0..2048) |
| 24 | 8 | accent percentages 0..100 |
| 32 | 32 | 8 × 4 phase shares 0..100, sum 100 for nonempty role else all zero |
| 64 | 8 | signed mean NUDGE -50..50 |
| 72 | 8 | mean absolute deviation around mean 0..100 |
| 80 | 4 | kick/snare co-onset share, empty-step share, final-quarter tom share, repeated adjacent group share (each 0..100) |
| 84 | 4 | FNV-1a |

Extractor uses a declared common grid and complete selected phrases, counts occupied cells rather than raw ratchet strikes, rate = zero if no hits, otherwise max(1, round(hits * division * 256 / (4 * track_length))) (apply accumulated denominator across selected phrases), accent share among hits, phase bin floor(4 * (step mod steps_per_quarter)/steps_per_quarter). Normalize phase counts to 100 by largest remainders, tie lower bin index. Round half up for nonnegative ratios, signed mean ties away from zero. If micro unknown or no hits, micro-known bit clear and mean/spread zero. If accent observations are unreliable or unavailable, accent-known bit clear and accent zero; uniform or missing velocities are not evidence of zero accents. Silent roles have zero rate, phase, accent, micro fields and known bits. Reject an all-silent profile. Co-onset = K&S positions / union K or S positions, rests = empty all-role positions / total positions, final-quarter tom share = TH/TL hits in final quarter of each phrase / all TH/TL hits, repeat = equal adjacent quarter group onset-role signatures / number of adjacent pairs within phrases (zero denominator -> zero). For meter with fractional quarters, extractor v1 accepts whole-quarter groups only or reports unsupported; no hidden remapping. Analyze several windows by accumulating counts before normalizing, not by averaging ratios. Report selected duration/meter, dropped notes, collisions and missing attributes; current songs_pattern.quantize merges same role/step hits in window, so don't infer exact ratchet count or velocity curve. For known 4/4 JSON use existing tempo/phase conversion; use a declared meter/grid for other inputs or refuse. Empty source is refused rather than learning a silent profile; an individual silent role is valid.

Editor import supports existing song-excerpt JSON and .gdn files initially; optional SMF import only using a verified local parser in a later PR within this feature, not a dependency for the FM-1. Decode strict length/version/ranges/hash, canonical zero fields and valid phase sums; decode failure preserves destination. Extract and export locally in browser, CLI uses the same fixture-defined arithmetic; no network. Profile blending off-device uses weighted integer interpolation and re-normalization of phase shares. Exact endpoints return the selected canonical profile unchanged. In an intermediate blend round each role's Q8 rate first; if zero, clear all four phase shares, accent, micro mean/spread and both known bits without phase normalization. Otherwise normalize contributing phase shares to 100 by largest remainder, ties lower bin; unknown micro/accent if either contributing parent lacks that data, with corresponding fields zero. Refuse an all-silent result without replacing the current profile. A rate of 1 at 25% plus rate 0 at 75% rounds to zero even if its contributing phase is 100. Factory styles supply rule parents; imported DNA statistically biases either hybrid or single style. Profile does not encode source's exact ordered notes and no guarantee of style imitation. Do not package song excerpts or third-party assets; use synthetic/rights-cleared fixtures, user-local input.

## 5. GENETIC BREEDING (DNA-03)

Native recipe GDR1: 126 bytes, versioned separately from GMC1. The generator keeps existing gm_config encoding intact. The recipe is a reproducible input, not a false claim of single-style GMC1 identity.

| Offset | Bytes | Meaning |
| --- | --- | --- |
| 0 | 4 | ASCII GDR1 |
| 4 | 1 | schema 1 |
| 5 | 1 | flags: bit0 profile present, rest zero |
| 6 | 2 | A, B IDs 1..22 |
| 8 | 5 | A mix, mutation strength, drummer ID 0..6, groove strength, riff strength |
| 13 | 4 | AGGR,DENS,CHAOS,HUMAN |
| 17 | 4 | grid num,den,division,bars |
| 21 | 1 | zero |
| 22 | 2 | BPM LE |
| 24 | 8 | seed u32, mutation index u32 |
| 32 | 2 | compatible GM_ENGINE_VERSION LE |
| 34 | 88 | canonical GDN1 or all zero |
| 122 | 4 | FNV-1a over 0..121 LE |

Except IDs, all macro values are 0..100. Nonzero groove strength requires a valid present profile; otherwise refuse. A present profile with groove=0 has no effect. ID0 drummer means off, not THE MACHINE (6). Recipe alone regenerates only when no live input is requested. Reproducible package additionally includes last completed riff frame (section 7) and protected base cells/timing/lock mask, stored externally; no promise that a seed can reproduce changed manual edits. A user-imported recipe is validated, never executed just by parsing. Recipe/native state and UI pending state separate. Active recipe stores the exact index used to generate the active candidate. Only explicit MUTATE proposes index=active.index+1 (unsigned wrap); it becomes active once on a changed committed candidate, never on preview, failed/no-change request or repeated ack. Ordinary Apply/replay uses the exact requested index; FOLLOW retains it and varies by frozen phrase, not hidden increments.

Algorithm:
- Derive parent configs with identical requested grid, BPM and macros, algorithm A/B, shared seed/index. Build both rule masks with gm_rules_build and verify same valid uniform lengths. For supported compatible DNA grids, at mix 100 or 0, with DNA/RIFF/DRUMMER/MUTATION enhancements disabled, use gm_generate with selected parent and unchanged base, byte-identical to existing generator. A==B with no enhancements is also legacy identity. This branch returns the original gm_generate result and legacy validation, plus existing effective protection, structural/onset and native-adapter checks, not DNA-only pair/anchor validation or optional-drop repair. For Hammer density 100, an optional K protected OFF can leave paired S ON: preserve those legacy bytes, not a stricter DNA-enhanced pair. Parent rule interpretation is retained per group (including Gravity/Industrial special accent logic).
- Intermediate mix: coherent quarter-note groups selected as whole sets across all eight roles, not independent random cells. Group count based on common grid; for 7/4 use existing 3+2+2 motif after EA1; segmented 11–13 and any indivisible phrase use whole-bar/whole-phrase selection or explicitly refuse incompatible intermediate crossover. For supported quarter groups, select exactly round(group_count * A_mix/100) A groups by deterministic rank keyed from seed, mutation, group and new domain 8, ties lower group. Others B. If only one indivisible group, show that choice; don't advertise it as a blend. Copy selected group's anchors, optional, required accent/ratchet, paired and forbidden masks, preserving group ownership. No union of incompatible anchor/rest masks. Never split an indivisible paired event; validate cross-group edges, old hard-rest semantics and selected rules.
- Optional candidate scoring: original density chance adjusted by explicit profile and riff weights; base opportunity scores 0..100. For an imported profile use phase preference relative to 25% uniform and rate relative to requested density: target occupancy percent = min(100, round(rate_q8 * 400 / (division*256))); profile_score = clamp(target occupancy + phase_share - 25,0,100). Before blending, adjust profile_score using immutable selected anchor masks: optional S on K anchor averages with co-onset share; an optional position without hard anchors across roles averages with 100-rests; optional TH/TL in final quarter averages with fill, elsewhere with 100-fill. Averages round half up. score = round((base_density*(100-groove)+profile_score*groove)/100). Riff K onset computes w=round(riff_strength*velocity/127), then score=round((score*(100-w)+100*w)/100); an empty riff slot uses round(score*(100-riff_strength)/100). Sustain-only slots retain score, no added K opportunity. Bias optional candidate timing/accents only where native bounds and required accents permit. Rate/phase use selected group's grid. For allowed elastic styles (Technical ID9, Brutal ID10, Chaos ID17, Industrial ID18, Stoner ID22), add K optional on non-forbidden riff onset when no hard K anchor, and eligible H/R/S non-forbidden optional opportunities plus TH/TL in the final quarter; preserve existing style identity and paired rules. Other styles start with existing optional masks only; hard blast anchors stay hard. Non-riff DNA profile still biases these elastic opportunities. No note-copy from guitar pitch.
- Mutation: gm_random domain 9 low bit selects whether to blend score with 100-score by mutation strength; otherwise leave score unchanged. Domain 10 chooses optional hits, domain 8 chooses groups. Repetition uses domain 11 with probability round(repeat*groove/100) to reuse the preceding equal-length group's corresponding optional decision key; do not copy cells/locks or split pairs. Known optional non-required accents interpolate legacy aggression toward imported accent share by groove strength, with domain 12, preserving mandatory Gravity/Industrial accent semantics. Known micro on optional cells uses domain 13 for a bounded signed deviation around profile mean, blends with legacy micro and clamps to legacy humanize/swing span and first-step constraints; unknown micro/accent leaves legacy behavior unchanged. Keep original 1..7 unchanged and old golden vectors byte-identical. Group selection may vary with mutation index, hard rules of selected group remain fixed; locks override. Optional paired decisions share one score/key. Riff rest in a required blast is not allowed to silence mandatory blast; user can select compatible stop-and-go/elastic parent. Empty riff data does not create all-rest pattern; report NO RIFF if FOLLOW requested.
- Build in existing unpublished scratch gmrt.out; failure may overwrite scratch only, never live or caller base. Preserve all protected cells using effective mask; copy original G-LOCK bits (not synthetic P-LOCK/MOTION bits) to output after validation. Share the existing cell generation/validator internals by refactoring rule-aware helpers rather than duplicate the 22 style engine. Existing public gm_generate contract (output untouched on failure) unchanged. Outside the legacy-identity branch, new DNA validation checks required anchors/rests/ratchets/accents, pairs and explicit protected overrides against effective masks, then existing structural/onset validation and native check. Never subsequently apply these DNA-only repairs/refusals to an accepted legacy-identity candidate. If optional hits violate portable capacity, drop optional groups in deterministic low-priority order and revalidate; if still impossible refuse. Never relax existing onset cap or required/locked hits. Do not use gm_validate(parent_config, mixed_pattern) as a substitute.

## 6. DRUMMER BRAIN (DNA-04)

| ID | Name | Character and controllable behaviors |
| --- | --- | --- |
| 0 | OFF | no human constraint or extra bias; original generator |
| 1 | THE MANIAC | dense fast phrases, aggressive accents, energetic fills, variable optional micro |
| 2 | THE SURGEON | technical syncopation and precise double kick, narrow micro |
| 3 | THE EXECUTIONER | forceful kick/snare, accent-led breakdowns |
| 4 | THE TITAN | lower optional density, deliberate space and tom/cymbal weight |
| 5 | THE ANARCHIST | odd grouping, syncopation, varied optional fills |
| 6 | THE MACHINE | deterministic motoric pulse, human limb heuristics bypassed, no bypass of native voice/onset constraints |

This is a musical heuristic, not a biomechanics model or medically meaningful fatigue. Assign virtual left/right hands to S/H/R/C/X/TH/TL, left/right feet alternate successive K onsets including ratchets. Cymbal choke remains native; no invented separate pedal voice. For uniform grid, derive nominal step/ratchet coordinates from signed micro and ratchet subdivisions, group equal positions, including collisions across adjacent steps and loop edge. Proposed integer unit = 1200 per step (100-percent nudge × 12, divisible by 1..4 ratchets): position = 1200*s + 12*micro + 1200*k/n, normalize modulo phrase length for steady loop; first-pass early hit semantics native. For unequal/swing-offset native timing this is only nominal, not claimed sample-exact; initial human-coordination mode uses uniform division/length with zero swing unless actual native event mapping is integrated; explicit refuse incompatible protected timing rather than modify it. Real native timing trace remains final verification. Max two simultaneous nominal hand strikes; assign hard/protected first, then highest optional score, tie track index. Sweep one-step nominal windows examining s-1/s/s+1 across loop wrap; choose next timestamp and group equal times without assuming adjacent cells are ordered. Alternate free-hand preference for single strokes, other hand for simultaneous. A parent with three mandatory simultaneous hand strikes may be refused: show LIMB CONFLICT, let player choose compatible parent or MACHINE. This is strike ownership, not a model of limb travel or maximum human speed. Drop/de-ratchet optional cells or paired optional groups and revalidate; if hard/locked events unassignable refuse, never edit the lock. Feet alternate by chronological strike, including successive same-step ratchets; do not emit two new kick voices or write pitch offsets to simulate feet. For K leg alternation and accents keep side metadata diagnostic/trigger-only; EA3 VARY can optionally voice the alternating kicks once implemented, no change to four-byte step format. Ghost notes in v1 mean optional non-accent cells (native 96 vs 127 accents), not continuous per-step velocity. EA3 may extend per-hit timbre; no claim of independent soft velocities before that. Fatigue is a deterministic second pass: count total provisional optional strikes, then walk phrase order and remove an optional cell/group if domain 14 roll is below floor(coefficient * prior_provisional_optional_strikes / max(1,total_provisional_optional_strikes)). Count from the immutable provisional selection or recompute from identical inputs including removed groups; apply pairs atomically. No circular score/total dependency, zero at start, reset next phrase. Required anchors unchanged. THE MACHINE has no fatigue. User HUMAN remains timing control, no uncontrolled playback RNG; no cumulative wall-clock learning.

## 7. RIFF INTELLIGENCE (DNA-05)

Input USB or TRS MIDI note-ons/offs with explicit source and channel, MIDI LEARN retains precedence, realtime clock/transport unchanged. Capture observes only a nonconflicting channel; refuse overlap with native drum channel / RT_TRACK ch1..8 / existing assigned MIDI learn notes (learned events stay their action, excluded from capture). No consuming native drum notes, no changes to THRU or MIDI out routing. Arm while stopped; verify no held notes on the selected source/channel from valid continuous input state maintained before ARM, not by initializing an empty bitmap at ARM. User starts PLAY (or external Start); CAPTURE collects exactly one complete native pattern cycle, FOLLOW continuously collects complete cycles. No automatic start or request triggered by a partial phrase. Can preview the last valid completed CAPTURE phrase after STOP if grid/context still matches; editor may import a fixed phrase without transport.

Frame: gm_grid (4 B), velocity[64] (max nonzero note-on velocity per active logical step, 0 absent), sustain[8] bitmask (any tracked note held during sampled step). 76-byte logical payload; length derived by gm_grid_length, zero past length, bit ordering same as KEEP for one row. Held MIDI pitch state: 16 B per USB/TRS source/channel (bounded 512 B table for 2 × 16 channels, or equivalent verified existing state source). Observe note state even while OFF, independent of filter selection, without consuming events or changing MIDI LEARN precedence; only eligible non-learned events enter capture bins. ARM reads the selected channel under the native guard. This tracks the observed device MIDI stream, not notes played before connection. Repeated on same pitch collapses to held (no polyphony inference), velocity-zero note-on is off; overlapping pitches union, unmatched offs harmless. On lost input events mark affected held state uncertain; do not zero it to permit ARM. A known input reset or observed All Notes Off for that source/channel re-establishes state without altering native routing. Measure tracker storage with existing native resource evidence. Two frame buffers with explicit ISR-write/main-read ownership and sequence; no raw unbounded event list. Frame is complete only after an entire native reference cycle and valid clock. Track a capture-context revision (meter/division/route/clock/source/slot) and frame identity; invalidate on MIDI overflow/drop, clock loss/change, context load/variation/restore or route change. STOP/disarm cancels partial capture and pending generation, retaining a valid completed CAPTURE frame only while context matches; FOLLOW never continues after STOP without explicit rearm. A missed frame can be replaced by newer complete frame; never overwrite a reader. If no free capture slot, drop new frame visibly, not partial old frame. No extra audio-thread loops over raw events. No generated MIDI is treated as input unless externally looped; document avoiding MIDI feedback.

Use existing midi_block source/timestamps and actual native reference-track logical phase, not wall-clock BPM guessing. Note events in a block before cue processing belong to the currently open native logical step, documented block quantization; when external clocks advance the block, use accepted native phase at block entry and carry step-close notification at seq_tick. A note on an exact boundary follows native packet/block order; never retroactively modify frozen frame. Capture at step 0 after explicit transport start; skip until next complete reference cycle if armed mid-cycle. Close last step before reference track restarts (including the native cue switch hook; a DNA self-commit at unchanged grid closes the old cycle and opens the next exactly once without invalidating its own capture), include sustained occupancy at step start/end and any on in step. Preserve held pitch state across phrase boundaries for legato and across STOP/disarm/filter changes for pre-arm detection. Context switches invalidate capture frames, not the continuous tracker; input loss/reset separately governs tracker validity. All native time/clock work belongs to existing events_block/seq_tick/cue; no new ticking scheduler. Native first release CAPTURE/FOLLOW requires uniform active cycle matching chosen recipe (no song/Grids/external unsupported sources/polymetric reference, no native cue pending when arming). Native external USB/TRS clock supported by same phase observation, lost clock stops as existing. Riff feature classification from bins: onset density, accent bins, interval changes, sustain vs empty slots, end rests/repeated groups; no pitch/articulation classifier. FOLLOW uses only newest complete frozen frame, does not predict future notes. At completion main queues candidate for an existing future END, cannot retroactively change the just-completed phrase; if it misses that boundary, next available END or newer submitted request wins. If frame F2 completes at a boundary where F1 was already consumed, F1's commit is legal; F2 affects only a later END. Arbitration is by submitted revisions, not future frames. Silence => WAIT RIFF, retain current pattern. New user edit or slot cue invalidates pending; FOLLOW remains disarmed on context change, explicit rearm required.

## 8. Native control, undo, UI, storage (DNA-06)

Pure core interfaces, proposed names:
    gd_profile_decode(bytes,len,out), gd_profile_encode(profile,bytes,cap)
    gd_recipe_decode(bytes,len,out), gd_recipe_encode(recipe,bytes,cap)
