# GRIND DNA ENGINE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the approved hybrid GRIND DNA ENGINE: deterministic breeding, learned groove statistics, human/machine drummer profiles and native MIDI riff response.

**Architecture:** The [design specification](../specs/2026-11-27-grind-dna-engine-design.md) defines GDN1/GDR1, coherent rule groups, protection precedence and a compact capture stream. Extend the existing C core and native cue lifecycle, and extend the local GRIND editor and song tool; share C with host/WASM. No second audio engine or scheduler. Additional reference h1 d239dbf (linked in design): bounded recorder/overflow, revision-bound export abort, real host/native testing. Use those patterns in GRIND fixtures, not h1's looper or a new release gate.

**Tech Stack:** C99 portable core, gnu11 native fixture, fixed-point/integer algorithms, Python stdlib, existing JS modules and Web MIDI, Emscripten, pinned JieLi Linux toolchain/SDK, existing GitHub Actions.
