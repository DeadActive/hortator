# BLE part 1a (port, link, shrink to fit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Hortator build with the JieLi BLE stack linked (`FELUCCA_BLE=1`) that fits the app slot with at least
32 KB free and the pool / RAM checks, while the default build stays byte-identical to `drum-v0.14.0`; it ends in a
measured go / no-go for part 1b.

**Architecture:** the BLE module from fm1-lsdj `main` 548ce73 (`firmware/src/ble/`, its own compilation unit
`ble.c`, reaching the core only through `ble_core.h` / `core_ble_api.c`) and its tools come over, adapted to
Hortator (frozen HAL untouched: a new `hal/fm1_ble_hal.h`; no UI; the slice 5 ms). `tools/build.py` gains the
`FELUCCA_BLE=1` path of fm1-lsdj's build (Docker, the pinned SDK V1.2.0 libraries through LLVMgold, `--wrap=memcpy`,
`app_ble.ld`). Then the stack is shrunk in measured steps (LTO-visible config and log stubs; classic / TWS
references) until it fits; RAM is fitted with 2 KB task stacks and a sized heap.

**Tech Stack:** C (JieLi pi32v2 clang, LLVMgold LTO for the SDK bitcode libraries), Python build tools, host tests in
C.

**Spec:** `docs/superpowers/specs/2026-10-08-ble-midi-design.md` (with its Amendments section)

## Review Focus

1. A default build after the port (no `FELUCCA_BLE`): byte-identical to `drum-v0.14.0` built the same day (the
   preprocessor guards really exclude everything). Test: Task 1 gate 5 script.
2. A BLE build with the SDK libraries' hashes not matching the pins (a different SDK): the build stops, naming the
   archive. Test: Task 1 step (a wrong `AC79_BT_SDK` path / a patched pin in a copy of `ble_libs.py`).
3. Library code meant for RAM landing in XIP, or `.ram_text` reaching XIP (the radio trim): the build stops. Test:
   Task 1's build checks (fm1-lsdj's reach check ported for BLE builds; Hortator's stricter no-call check kept for the
   default build).
4. Dropping the log strings / classic paths changes behaviour the BLE central needs (a stub that returns the wrong
   value): the host tests (`tests/ble/*`) stay green and the dropped symbols are listed in `docs/ble/FIT.md` for the
   1b device test. Test: Task 2 / 3 steps.
5. RAM: the pool keeps ≥ 8 KB headroom and `.data` + `.bss` ≤ 96 KB with the BLE build; the heap high-water is
   reported (for 1b's measured sizing). Test: Task 4.
