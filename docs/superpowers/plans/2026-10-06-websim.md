# FM-1 web simulator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a public web page that runs the real FM-1 drum firmware (compiled to wasm) with its screen, panel, LEDs and stereo audio.

**Architecture:** one C translation unit (`tests/sim_core.c` → `tests/sim_host.h` → the `firmware/src/*.c` sources) exports a small API. It is built with plain `cc` for headless tests and with emcc (Docker) as a standalone `.wasm`. `web/sim/engine.js` wraps the wasm. It runs inside an AudioWorklet in the browser and in node for tests. The page draws the panel and talks to the worklet by `postMessage`.

**Tech Stack:** C (firmware sources, as-is), emscripten in Docker (`emscripten/emsdk`, pinned), vanilla ES modules, AudioWorklet, IndexedDB, node (tests).

**Spec:** `docs/superpowers/specs/2026-10-06-websim-design.md`

## Global Constraints

- New files only: `web/sim/**`, `tests/sim_*.{c,h,mjs}`, `tools/build_sim.sh`, `docs/SIMULATOR.md`, `docs/superpowers/{specs,plans}/*websim*`. Never edit `firmware/**` or existing shared files.
- Build output only under `build/sim/` (generated headers in `build/sim/gen`). Scratch files in the worktree.
- New source files carry `/* SPDX-License-Identifier: GPL-3.0-only` + `Drum machine fork: 2026 DEADACTIVE */` (JS: `//` comments, same text).
- Commits only on `web-sim`; no push, no merge, no WebMIDI output, no SysEx, no device tools.
- Audio at 44100 Hz (`FS`); `CTL` = 32; `HALF_FRAMES` = 256; worklet quantum 128.
- Local serving on port 8001, never 8000.
- No SharedArrayBuffer, no COOP/COEP: any static host.

## Review Focus

- A window losing focus / a tab hidden while a key or button is held → everything is released (no stuck notes). Test: glue test `releaseAll()` clears levels; page calls it on `blur` / `visibilitychange`.
- Keyboard autorepeat (`e.repeat`) → ignored, so no repeated presses. Test: glue test on the keyboard handler's pure function.
- Two inputs holding the same control (a finger and a keyboard key) → releasing one keeps it held. Test: glue test of the refcounted control state.
- A pointer that slides off a key or gets cancelled → the key is released. The page uses pointer capture plus `pointercancel`. Checked by hand; covered in the screenshot pass.
- Corrupt or stale flash sectors in IndexedDB (an older firmware build) → the firmware's own `persist_boot` validates them (boot_test covers hostile flash). Test: the host test boots on random bytes in the store area and must not crash.

- [ ] **Step 5: `tests/sim_core.c`.**
  - `sim_init(fresh)`: if fresh, `sim_flash_reset()`. Then `fm1_main`'s order: `persist_boot(); settings_init(); felucca_dbg` reset as in `main.c`; `panel_init(); drum_boot_init(); audio_init();`. Then `lcd_fill(0,0,240,240,C_BLACK); ui.force = 1; song.batt_raw = 600;`. If fresh, `sim_demo_install()` (Task 3; until then a stub in sim_core.c).
  - `sim_render`: a pending buffer of one half. When empty, `sim_half ^= 1; fm1_alnk0_irq(); sim_samples += HALF_FRAMES`. Convert to float `/ 8388608.0f`. Whenever `sim_samples >= next_frame`, run `sim_frame()` and set `next_frame += 15 * 441 / 10` (15 ms).
  - `sim_frame`: `main.c`'s loop body without hardware. The MASTER IIR `knob += (a*16 - knob)/8` and `master_q12 = (k10*k10)>>8` from `sim_master`'s value; the `felucca_dbg` breadcrumbs; `ui_input(); ui_leds(); ui_draw();`.
  - `sim_btn`: set or clear `fm1_in.buttons` bit `panel.btn[label]`; on down, OR it into `fm1_in.pressed`.
  - `sim_key`: same on `fm1_in.notes` / `notes_pressed`, bit n.
  - `sim_enc`: `sim_enc_acc[panel.enc[role]] += steps * panel.dir[role]`.
  - `sim_leds`: for labels b: `led_lit(panel.btn[b])`; for keys n: `led_lit(14+n)`. `led_lit(id)` scans `FM1_KEYMAP` rows 1..4 for id and tests `fm1_led[col] >> row & 1`.
